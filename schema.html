Subtopic schema

MeshEMS publishes JSON. The desk only listens. Temperature on the wire is always Celsius. One board keeps the relay and the setpoint. Nothing in this page is a command.

The board desk reads a local log of these same publishes. The log keeps running when the site is closed. Start it with node log/record.mjs. The log also keeps nesl_coldems/#.

COLD-EMS on the public broker uses nesl_coldems/<deviceId>/state and nesl_coldems/<deviceId>/COLDAMI/mains. mains.phases.A|B|C.voltage_ln and real_power_w drive the packhouse feeder when a phase is actually up. COLDAMI/leakage and COLDAMI/alerts raise the corner sentence when a sensor alarm is set. The desk does not publish.

The same two payloads cover a clinic cabinet, a fish hold, and a packhouse room. A site with several cold systems repeats the environment payload, once per system. Bands, stock, and money stay on the desk. They are not sensor fields.

Rules for every trade

  • temperature_C is degrees Celsius. The desk may display Fahrenheit. It does not write Fahrenheit back.
  • temperature_C: 0 together with humidity_percent: 0 means the probe is not live. The desk keeps the last real sample.
  • location_text of North_Pole or Unknown Location is the firmware placeholder. The desk ignores it.
  • door_open_duration_ms is the length of the opening that just finished. While the door is open the desk times it locally. A hatch, a lid, and a cabinet door are the same boolean.
  • WphA, WphB, WphC are watts. PhVphA/B/C are volts. TotWhImport is watt-hours since the meter started, already scaled. The desk shows the change since it first saw the counter.
  • All phase volts under about 40 V is a supply loss. Watts still sum.
  • timestamp_ms on the board is millis(), not a Unix time.
  • latitude_deg and longitude_deg are on the environment object. The desk does not move a map pin from them. Position for a simulated feed is the GeoJSON point, [longitude, latitude].
  • One device id binds to one room. A second room needs its own environment publication. A real id that is already live is not overwritten by a sim- point.
  • The desk does not publish …/cmd.
  • maintenance is proposed. It is not a command. A present message is the sentence a person should act on. An empty message, or null, clears it. The desk does not invent this field onto a live board.

Several cold systems on one node

Proposed When one MeshEMS watches more than one cabinet, repeat the environment object. The keys do not change. The room id is the path, not a new field.

openami/<deviceId>/room/vaccine/env
openami/<deviceId>/room/oxy/env
openami/<deviceId>/room/insulin/env
openami/<deviceId>/subpanel_3Ph

Shared supply stays on subpanel_3Ph. Publish room/<roomId>/power only when that cabinet has its own meter. The JSON there is the 3Ph object.

Until the desk routes room/…, give each cold system its own device id and publish subpanel_ENV on each. Put subpanel_3Ph on the id that owns the meter. That path works on the desk now.

What is not a feed

Safe band, freeze threshold, humidity band, stock count, price, holdover hours, and the action sentence are operator settings on the desk. Outage, freeze, dry air, and a warm lid are judgments from the fields above. Do not add status, alarm, or temperature_F to the board payload.
